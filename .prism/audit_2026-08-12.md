## Observation carried into this run's feature selection

`app.py`'s own Overview-tab comment (around the "Agent Summary" block)
documents the gap directly: `insight_orchestrator.orchestrate_insights()`
is a **pure synthesis layer** — it never triggers detection itself, only
reads whatever `st.session_state` slots detectors have already populated.
`auto_insights` and `confounder_scan` run automatically on
`set_active_dataset()` (upload), but `hypothesis_sweep_result` and
`anomaly_result_df` only populate when the user manually opens Stats Lab /
the Overview "Anomaly Detection" expander and clicks their own button.
Both of those are fully automatic, deterministic, dataset-wide checks
(`hypothesis_sweep.sweep_hypotheses()`, `anomaly.find_anomalies()`) that
need **no additional user input** (no column/target selection, unlike
Causal Effect Estimator or Drift) — so there's no reason they can't be
fired from a single explicit "Run Full Analysis" action instead of
requiring two separate tab visits before the Agent Summary has enough
detectors to stop being silent (`MIN_DETECTORS_FOR_OUTPUT = 2`).

This confirms Run 25's option (b) recommendation is real and
well-scoped, not just plausible — selected as this run's feature (see
`.prism/research_2026-08-12.md` and `.prism/routine_log.md`).
