## Investigated this run: light-theme dataframe canvas styling (Run 6's open finding)

Run 6 left this ambiguous: a Playwright screenshot taken via a live
in-session theme switch showed dark canvas-row styling on the Overview
"Missing Values"/"Outliers" tables, despite Run 4's `sync_native_theme()`
fix — but Run 6 didn't test a genuine fresh page load on light theme, so
it wasn't clear if this was a real regression or a same-session repaint
lag.

Tested both scenarios this run:
1. **In-session theme switch → load dataset → view tables**: correct
   light styling (white background, dark text, no dark banding) — see
   `.prism/runs/2026-08-10-run7/05_light_theme_dataframes_check.png`.
2. **Genuine browser reload while `theme_mode` session state is Arctic**:
   Streamlit resets the *entire* session on a hard reload (dataset
   unloads, back to the landing screen, theme reverts to the graphite
   default) — there is no code path where a user actually lands on the
   dataframe tables in light theme without having gone through the
   in-session toggle first, since the toggle is the only way to reach
   light theme in the first place.

**Conclusion: this backlog item does not reproduce.** `sync_native_theme()`
(Run 4) is working correctly. Closing it — Run 6's screenshot was most
likely the same-session repaint lag it already suspected, not a
regression. Future runs: drop this from the backlog.

## New findings this run

- The Causal Effect Estimator panel built this run initially rendered its
  four result metrics (ATT, 95% CI, matched pairs, match rate) in four
  `st.metric` tiles at 1440px width — the CI (`[-0.829, 1.67]`) and
  matched-pairs (`172 of 200 treated units`) strings were long enough to
  visually truncate inside the metric tile. Caught in Phase 5 screenshot
  review, not shipped. Fixed by keeping only the two short values (ATT,
  match rate) as metric tiles and moving the longer CI/matched-pairs text
  to a `st.caption` line below — see routine log for detail. General
  lesson for future `st.metric` usage: keep tile values short (a number, a
  percent, a small bracketed pair at most); anything with more than ~15
  characters belongs in a caption instead.
