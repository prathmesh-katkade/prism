## Findings

### 1. Mobile Atlas panel overlap — root cause was NOT what two prior runs assumed

Both 2026-08-07 Run 2 and 2026-08-10 Run 3 described this as "the Atlas
side panel doesn't reflow at ~390px." That's true but incomplete. Layout
inspection (Playwright `getBoundingClientRect` + `getComputedStyle` on the
live DOM, not just a visual screenshot) found **two independent causes**:

1. `.st-key-atlas_side_panel` (`modules/theme.py`) — `position: fixed;
   width: 328px`, unconditional, no media query.
2. `app.py`'s Atlas-panel render block separately injects
   `<style>.block-container{padding-right:352px !important;}</style>` to
   reserve room for (1) — *also* unconditional.

Fixing only (1) (which is what the two prior runs' descriptions would lead
you to do) still leaves (2) alone reserving 352px of a 390px viewport for
main content, i.e. ~22px usable width — confirmed by measuring
`stMainBlockContainer`'s computed `padding` directly
(`96px 352px 120px 16px`) after an initial CSS-only fix still looked
broken in a screenshot. Both are now scoped to the same 768px breakpoint.
**Lesson for future runs:** a screenshot alone doesn't tell you *why* a
layout is broken — when a CSS fix doesn't visibly change a broken
screenshot, inspect computed styles/bounding boxes before concluding the
fix is wrong or the bug is elsewhere.

### 2. Light-theme dataframe styling — root cause confirmed

`st.dataframe`/`st.table` render via glide-data-grid, a `<canvas>` element.
Canvas fill colors come from Streamlit's `theme.base`/`backgroundColor`/etc.
*runtime config*, not CSS — confirmed by checking `st._config.get_option`
values live (defaulted to `.streamlit/config.toml`'s hardcoded
`base = "dark"`, never updated when the in-app theme toggle switched
`theme_mode` in session state). Fixed via `st._config.set_option`, the same
private API most third-party Streamlit theme-toggle implementations rely
on (there's no public API for runtime theme switching as of Streamlit
1.50) — guarded in a try/except.
