## Findings

1. **(Re-confirmed, refined) Light-theme canvas repaint lag on in-session
   theme toggle.** Run 6 found dark banding on `st.dataframe` tables after
   an in-session theme switch; Run 7 investigated and reported "does not
   reproduce" on both the in-session toggle path and a genuine reload. This
   run reproduces it precisely under one specific sequence: **interact with
   a panel first (render a dataframe/Plotly chart under the active theme),
   then switch themes** — the already-mounted `st.dataframe` (glide-data-grid
   canvas) and Plotly chart keep their stale dark styling until a fresh
   remount, while newly-rendered widgets pick up the new theme correctly.
   Switching theme *before* interacting with the panel (Run 7's tested
   order) renders cleanly, which is why it looked fixed. This is a Streamlit/
   Plotly component lifecycle quirk (stale canvas, not app logic) — not
   chased further this run given three prior sessions' worth of investigation
   already sunk into it, but the precise repro steps are now on record so a
   future run doesn't have to re-discover them. Not a regression from this
   run's changes — reproduces identically on pre-existing panels (e.g. the
   original Causal Effect Estimator's balance table).
2. **No other regressions found.** Auto Cleaner, Confounder Check, Causal
   Effect Estimator, Hypothesis Sweep, Feature Selection Engine, SQL Lab
   (DuckDB), Atlas panel, and theme switching all still work as documented
   in prior runs' audits.
3. **Verified live, both new features (see RUN_REPORT for detail):**
   CATE subgroup heterogeneity correctly detects an injected sign reversal
   on a synthetic campaign dataset (desktop dark/light, mobile dark); the
   DuckDB large-file path correctly routes a 500,000-row/16.6MB upload
   through Smart Sampling with visibly shuffled (non-sequential) IDs after
   sampling, confirming true random sampling rather than first-N truncation.
