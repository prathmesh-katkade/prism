# Prism Audit — 2026-08-07

## Method
Booted the app locally (`streamlit run app.py --server.headless true`),
loaded the bundled "Sales" sample dataset, and walked the primary nav
(Overview → Clean → Visualize → SQL Lab → AI Analyst) plus the Advanced
Tools popover (Auto Analyst, Hell Mode, Combine, Stats Lab, Forecasting,
Clustering, Domain Lens, Geo Lens, ML Lab). Checked desktop (1440×900),
mobile-PWA width (390×844), and both the App Preferences theme toggle
paths. Cross-referenced against `git log` to see what prior sessions
already shipped, and read the core agentic modules (`auto_analyst.py`,
`atlas.py`, `anomaly.py`) end to end.

## What's already strong (don't rebuild)
- Auto Analyst: Gemini plans a 4-6 step EDA, runs each step through a
  sandboxed pandas executor, synthesizes 5 headline findings. Real
  agentic pipeline, not a single prompt.
- Atlas: proactive ambient insights on every fresh dataset load
  (`announce_ambient_insights`), a real multi-step planner
  (`_cmd_propose_plan` / `_cmd_execute_plan`), voice input.
- SQL Lab: full DuckDB workbench with data-quality test badges
  (`b-pass`/`b-fail`/`b-err` — the pattern this run's new verification
  badges reuse).
- SHAP explainability, IsolationForest anomaly detection, Titan
  Enrichment (Open-Meteo), Chaos Intensity stress test, a 15-dataset
  benchmark harness with hardening fixes for LFI/SSRF in the AI code
  sandbox. This is a genuinely deep feature set already.
- Glassmorphic HUD theme system is consistent — one CSS template
  (`modules/theme.py`) substituted per theme, not per-tab reimplementation.
  Dark/light toggle intact, mobile viewport doesn't overflow or clip.

## Gaps found this run
1. **Zero automated tests anywhere in the repo.** No `tests/` directory,
   no `pytest` in requirements, no CI test step referenced. For a
   ~200KB application with real statistical/ML logic, this is the
   single weakest point against a data-science hiring panel — "how do
   you know this is correct" had no evidence to point to. **Fixed this
   run**: 22 pytest tests added covering the new module plus two
   previously-untested ones (`anomaly.py`, `auto_analyst.py`).
2. **No self-verification on LLM-synthesized findings.** Auto Analyst's
   `synthesize_findings()` trusts Gemini's numbers as-is — a classic
   "plausible but wrong" hallucination risk in agentic EDA. **Fixed this
   run**: `modules/insight_verifier.py` recomputes real statistics from
   the DataFrame and flags any finding whose numbers don't match.
3. **Deprecated Gemini SDK.** `google.generativeai` now raises a
   `FutureWarning` on import (upstream support ended in favor of
   `google.genai`). Not broken yet, but worth a dedicated migration run
   — touches every Gemini call site, out of scope for a quick patch.
4. **No live Gemini key in this execution sandbox** — Auto Analyst,
   AI Analyst, and Atlas's LLM features all show the (correctly
   designed, non-crashing) "add your free Gemini API key" empty state
   instead of running live. This is expected/by-design for a sandboxed
   CI-style environment, not a bug — flagging so the next run's audit
   isn't surprised by the same thing.
5. Minor: dataset-loaded Overview view puts the raw data preview above
   the nav pills on first paint, so a first-time user has to scroll to
   find navigation. Cosmetic, low priority — not touched this run to
   keep the change surface small and reviewable.

## Weak spots vs. a hiring panel's likely questions
- "How do you validate the AI's output isn't hallucinating?" → now has
  a real, demoable answer (Insight Verifier).
- "Show me your test suite." → now has one, with a documented `pytest`
  entry point (`pytest.ini`, `requirements-dev.txt`).
- "How would this scale to a 10GB file?" → still pandas-only outside
  SQL Lab; noted as backlog, not solved this run (architecture-adjacent,
  needs a dedicated run per the routine's own guardrails).
