These controls ran on the V1 90-item corpus. All generation runs used Ollama 0.34.4, temperature 0, `think: false`, `num_predict: 256`, `num_ctx: 4096`, and the same decoder JSON Schema. The only difference in Control A was the prompt envelope. All five runs were written to the durable AtlasBench store as generic diagnostics; none is a promotion run.

The nested Phi rerun scored 24, one item above the preceding transient 23/90 diagnostic. The predeclared interpretation covered a material rise or a score near 23. The material fall to 9 meets neither branch. OLMo's 38-item rise shows the nested envelope is a large confound for that model. The two effects point in opposite directions; no single prompt envelope can yet be declared a neutral capability measure across these models.

## Control B: full choice-string log likelihood

**Blocked; no scores reported.** A local `/api/generate` probe with `logprobs: true`, `top_logprobs: 20`, and `num_predict: 1` returned HTTP 200 and a `logprobs` array for the generated token `B`, with alternatives for that token position. The API [documents output-token log probabilities](https://github.com/ollama/ollama/blob/main/docs/openapi.yaml). This does not provide conditional log likelihood for each full candidate choice string without generating it. A one-token A/B/C/D ranking would be a different control, so it was not substituted.
